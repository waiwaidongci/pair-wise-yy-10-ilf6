# zfl-42 漆线雕返修解锁台

独立静态前端应用，直接打开 `index.html` 即可使用（无需构建、无运行时依赖）。

## 业务拆分（三个业务源码）

| 文件 | 职责 |
| --- | --- |
| `rework-judge.js` | **返修判定**：返修单受理/修复/回退/完成/复核/失效、领料冻结、职责分离、重复并发归并。不访问 DOM。 |
| `occupation-ledger.js` | **占用账本**：线材批次余量、领料占位/释放、阴干位顺序、刷新后对账。纯数据操作，不访问 DOM。 |
| `page-state.js` | **页面状态**：界面渲染、对话框交互、localStorage 持久化与刷新后对账编排。规则一律委托前两者。 |

返修单与作品、批次、工位的状态全部落在一个 localStorage 账本（`zfl42ReworkStationV1`）中。

## 核心规则

- **单件单未结束单**：每件作品同时只保留一张未结束返修单；重复或并发申请沿用首次受理单（加载时若发现多张，保留最早创建的，其余失效）。
- **缺陷冻结领料**：登记断线/翘线后只阻止新的领料，已占用的线材批次维持占位、余量不还。
- **复核解锁、职责分离**：返修完成须由「未登记该单任何缺陷」的师傅复核；缺陷登记人无法点击复核。
- **进度回退方案**：进度回退登记「误占批次释放 + 阴干位重排」方案，复核通过前批次只挂“待释放”仍占位、阴干位不动、进度不落定；驳回复核则全部恢复占位。
- **胎体/纹样修正**：修正胎体材质或纹样主题会使当前未结束返修单失效，未结案缺陷随单结案、领料解冻；可重新登记缺陷申请返修。
- **刷新一致**：每次加载都先对账——批次余量按占位重算、悬空/无复核依据的待释放批次恢复占位、阴干位去重并剔除非待阴干作品、重复返修单归并。

## 返修单状态

已受理 → 修复中 → 待复核 → 复核通过；任一未结束状态可被胎体/纹样修正置为「已失效」；复核驳回退回修复中。

## 测试

```bash
node test-rules.js     # 业务规则冒烟（纯 Node，无依赖）
node test-render.js    # jsdom 渲染冒烟（可选，需 npm i -D jsdom）
```

## 数据迁移

旧版 `zfl42Works` 作品数据在首次打开时自动迁移：旧“缺陷位置”文本转为缺陷记录，待阴干作品进入阴干位队列；迁移后清除旧键。
